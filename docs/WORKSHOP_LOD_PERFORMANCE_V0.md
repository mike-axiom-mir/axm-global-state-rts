# Workshop detailed vs LOD1 target-cost experiment v0

Status: EXPERIMENTAL / target-relative evidence only.

This lane continues the real cross-machine workshop path after Global State RTS proved the fresh Universal Creation workshop can be rebuilt, semantically verified, hash-bound, imported and visibly rendered in Chromium.

## Question

At ordinary RTS presentation distance and under local split-screen, how much target-runtime cost does the detailed workshop carry relative to its current LOD1, and what cost surfaces remain unchanged?

## Method

The workflow rebuilds the exact pinned Universal Creation specialist source with the same explicit Blender 4.3 route used by the producer. It verifies semantic continuity before measurement, then serves both generated GLBs through the actual Global State RTS local browser runtime.

For both 1-seat and 4-seat local-RTS views, the browser test installs either the detailed or LOD1 workshop into every active seat and records:

- per-asset triangle/material/image/mesh/primitive counts;
- aggregate decoded asset surface across active seats;
- installation time observed in the browser;
- requestAnimationFrame interval summary over a bounded sample window;
- JS heap data when Chromium exposes it;
- target screenshots for detailed and LOD1 at the same local-RTS integration seam.

## Current known geometry surface

Detailed workshop: 190,431 triangles, 19 material batches, 47 embedded images.

LOD1: 68,534 triangles, 19 material batches, 47 embedded images.

The geometry reduction is therefore substantial, but the current LOD does not reduce material or embedded-image count. This experiment measures that distinction in the consumer rather than calling LOD1 automatically cheaper in every dimension.

## Truth boundary

GitHub-hosted headless Chromium is a repeatable relative comparison surface, not a target-device FPS certification. The test does not establish mobile/desktop hardware acceptance, production frame budgets, collision, navigation, LOD perceptual equivalence or split-screen readability by assertion.

Screenshots require visual inspection. Timing deltas are descriptive for the exact CI run and must not be converted into a universal FPS claim.
